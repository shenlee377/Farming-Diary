# 農田日記 — 成本模型與上限策略（COST_MODEL）

> 狀態：結構與用量假設。**本文件刻意不填單價**：所有單價須於採用前查官方價目頁，並在表中記錄查證日期與區域。舊版 `ARCHITECTURE_PHASE_0.md` 中的金額與「Cloud SQL scale-to-zero」說法未經查證，不採用。
> 最後更新：2026-10-20

## 1. 成本來源分類

### 1.1 服務固定或最低成本（即使沒人使用也會產生）

| 項目 | 會不會閒置計費 | 降低方式 |
| --- | --- | --- |
| Cloud SQL 執行個體（vCPU／記憶體／磁碟） | **會**，執行中即計費；磁碟與備份即使停止也計費 | local 用 Docker；staging 用最小規格並在不用時停止；production 從最小規格起步 |
| Cloud SQL 公網 IP／連線方式 | 依設定可能有費用 | 待查證 |
| Cloud Run（min-instances = 0） | 不會（無請求時不計 CPU／記憶體） | 保持 0；冷啟動可接受 |
| Cloud Run（min-instances ≥ 1） | 會 | 第一版不設 |
| Artifact Registry 映像儲存 | 依容量 | 清理舊映像的保留政策 |
| Secret Manager、KMS 金鑰版本 | 依版本數、金鑰數 | 少量 |
| Apple Developer Program 年費 | 固定年費 | — |
| Google Play 開發者帳號 | 一次性（目前 APK 走 GitHub 公開下載，可不需要） | 若不上架 Play 可省 |
| 網域 | 年費 | — |

### 1.2 依請求與儲存成長

| 項目 | 計量單位 | 主要驅動因子 |
| --- | --- | --- |
| Cloud Run 請求、vCPU 秒、GiB 秒 | 每次請求 + 執行時間 | 活躍使用者、同步頻率 |
| Cloud Storage 儲存 | GB-月（依儲存類別） | 照片數 × 平均大小 |
| Cloud Storage 操作 | Class A／B 操作次數 | 上傳、縮圖、讀取 |
| 網路輸出 | GB | 使用者查看原圖次數 |
| Cloud Tasks | 操作次數 | 每張照片的處理任務 |
| Google Maps SDK | 地圖載入次數（行動 SDK 計費規則待查證） | 開啟地圖頁次數 |
| FCM | 推播（目前一般為免費，待查證） | — |
| 日誌（Cloud Logging） | 寫入量 GB | 日誌等級與量 |

### 1.3 AI 與 GPU 處理

| 項目 | 計量 | 控制 |
| --- | --- | --- |
| 對話模型 | 輸入／輸出 token | 每工作空間月度 token 上限；摘要先查 DB 再送模型，不把整個資料庫塞進 prompt |
| 影像分析 | 每張或每 token | 只對使用者選定的照片；縮圖送分析 |
| 三維重建 GPU | GPU 分鐘 | 階段 5；需手動觸發、單 job 逾時、並行上限 1、每月分鐘上限 |
| 語音轉文字 | 音訊分鐘 | 單段長度上限；先在裝置端判斷是否需要 |

### 1.4 開發與正式環境

| 環境 | 長駐成本 | 說明 |
| --- | --- | --- |
| local | 0（本機 Docker） | — |
| staging | Cloud SQL 最小規格（可停機）+ 其他按量 | 不使用時停止 Cloud SQL |
| production | Cloud SQL（含備份、可選高可用）+ 其他按量 | 高可用（HA）約使 DB 成本加倍，第一版不開，靠備份與 PITR |

## 3. 估算公式

```text
月成本 ≈ Cloud SQL 固定（vCPU 時數 + 記憶體時數 + 磁碟 GB-月 + 備份 GB-月）
       + Cloud Run（請求數 × 單價 + vCPU 秒 × 單價 + GiB 秒 × 單價 − 免費額度）
       + GCS（儲存 GB-月 × 類別單價 + Class A 次數 + Class B 次數 + 輸出 GB）
       + Maps（地圖載入 × 單價 − 免費額度）
       + AI（token × 單價）+ GPU（分鐘 × 單價）
       + 日誌、Secret、Tasks（多半極小）
```

## 4. 上限策略

1. **Billing budget + 警報**：dev／prod 各設預算與 50%／90%／100% 警報。注意：預算警報**不會自動停止**服務。
2. **硬性限制在程式內**：每工作空間每日上傳張數與 GB、每月 AI token、每月 GPU 分鐘、同時處理工作數；超過時回傳清楚錯誤與下次重置時間。
3. **Cloud Run**：`max-instances` 設上限（例如 API 5、worker 3），併發與逾時設定明確。
4. **GCS 生命週期**：原檔 90 天後轉低頻儲存類別（需先確認讀取模式與最短儲存期限費用）；被拒絕的附件與孤立上傳定期清除。
5. **Maps key 限制**：限制套件名稱／Bundle ID 與 API，設每日配額。
6. **緊急停止**：設定旗標 `AI_ENABLED`、`PROCESSING_ENABLED`，可不重新部署即關閉高成本功能；核心農務功能不受影響。
7. 可選：預算 Pub/Sub 通知 → 自動把上述旗標關閉（階段 3 前評估）。
